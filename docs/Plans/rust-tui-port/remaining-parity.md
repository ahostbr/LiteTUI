## Load flake: playback-stop (root cause fixed, UNVERIFIED under real load)

2026-11-05, one gate failure of `runtime_controls_process::selected_response_playback_reviews_exact_text_and_preserves_remote_ownership`, case `playback-stop`: "Unexpected prompt response" then a shutdown timeout. There was no prompt response racing the Stop path. The message is the generic fall-through for any response this side does not own, and here it was the source's failed joined shutdown. Cause: the playback helper runs in an owned job with its `speech-*` directory as cwd, and Windows can keep that directory pinned after the job reports no active process (6 of 40 and 8 of 40 immediate removals failed on an idle machine, the lock lasting up to 450 ms). `native_playback.retire()` removed it with one `TemporaryDirectory.cleanup()`, so the close, and then the shutdown that followed within the same window, raised PermissionError WinError 32; the source answered ok=false and never exited. The failed run's empty `recordings/speech-3oawe7da` is the directory whose rmdir failed. Fix: `_remove_directory()` retries only that sharing violation for `DIRECTORY_RELEASE_WAIT_S` (10 s) and then still raises; a failed joined shutdown is now reported with the source's own text. The `playback-stop` and `playback-quit` fixture cases pin the directory for 1.5 s from outside the job, which reproduced the exact failure deterministically before the fix. `native_dictation.retire()` now shares the bounded cleanup helper and has deterministic Apply/Cancel/Quit, retained-failure and retry coverage.

## Load flake: host-quit-parked (root cause fixed, UNVERIFIED under real load)

2026-11-05, one gate failure of `runtime_controls_process::finish_stop_and_quit_while_control_readback_is_held`, case `host-quit-parked`: "Runtime control owner differs from the exact admitted stream". On Quit the source writes the quit-drained stream's turn_end and the held readback in either order, and reads the readback's owner at publication. This side never records a terminal outcome for a quit turn_end and never settles that turn, so an owner of idle (or terminal) after the observed end was rejected; before the end the owner was still active and passed, hence the order dependence. Fix: `Turn` records `quit_ended` and the idle, terminal and settled-predecessor checks accept it as the retirement evidence; an owner claim with no observed end, a foreign origin or other owned work is still refused. The new `host-quit-parked-late` case holds the readback until turn_end has been written and failed with the exact message before the fix.

## Resolved flake: compact EOF during a question

`tests/test_rust_compact_process.py::test_quit_and_real_pipe_eof_retire_workers_inputs_and_callbacks_before_lease_release[eof-question]` (and `-wake`) timed out on `assert reached` (6de0332b and the Codex baseline 2544c3e6).
