## Architecture decision

The existing `--rpc` process runs `LiteTUI.run(headless=True)` and still creates Textual objects. Retaining that internal headless host is deliberate during the UI-first migration; it is not a finished runtime extraction and may limit early memory improvements. No legacy Textual screen is to replace a required Rust screen in the parity release.

Proposed Rust implementation: one crate at `rust/litetui-terminal/`, using Ratatui, Crossterm and Serde/serde_json. The implementer must resolve and lock versions compatible with the measured Rust 1.92 toolchain before coding. Use a bounded transport queue, dedicated child-I/O readers, an explicit event reducer and a terminal cleanup guard. Keep layout and provider logic separate without introducing a speculative plugin ABI or rewriting providers.

### Bounded raw-ingress transport foundation

`transport::Inbound` now provides a single-generation raw JSONL FIFO plus a separately bounded partial frame. Explicit positive limits constrain per-frame bytes (LF excluded, CR included), queued frame count and aggregate original queued bytes (LF included). No whole input chunk is copied and no JSON is reserialized. Popping transfers frame ownership and releases its queue charge; allocator overhead, capacity, borrowed input and consumer-owned popped frames are outside these logical bounds.

Overload is an explicit fail-stop fault, not async backpressure. Queue checks precede each frame insertion; a failing frame/suffix is discarded, earlier accepted frames remain drainable, and the first fault cannot be reset by later feeds, drains or EOF. Stale-generation calls cannot affect an active partial frame or terminal state. EOF with a partial fragment faults; frame-boundary EOF is closure, never work completion. The actual decoder's blank-line convention is preserved, including its deliberate distinction between form feed and vertical tab.

The consumer must stop new work on terminal ingress, drain the accepted prefix before propagating transport uncertainty, and stop protocol delivery on decoder failure without replaying remaining raw frames through a replacement decoder. An already accepted stream terminal remains observed when later ingress fails. These are explicit owner obligations; this primitive does not yet implement the session owner, async pipes, writer/stderr path, cancellation or process cleanup.
